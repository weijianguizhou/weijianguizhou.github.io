# Markdown 小记

这篇是被问出来的。同学看我拿 Obsidian 记笔记，问「Markdown 怎么用」；我讲了两遍，发现每次都从「井号后面要加空格」开始，索性写成一篇，以后直接甩链接。

Markdown 是一种轻量级标记语言：用纯文本写，用几个简单符号排版，目标是「易读易写」。它不像 LaTeX 那样要编译出一份 PDF，源文件本身读起来就接近成品的结构——写给自己的笔记，或者发到网上的文章，用它是真的快。

这个博客的每一篇也都是 Markdown 写的：新建一个 `.md` 文件，写完推送到 GitHub，站点自动重新构建。所以这篇既是用法小记，也算是我自己的写作流程说明。

## 一、编辑器：Obsidian 和 VSCode

### Obsidian

我记笔记主要用 Obsidian，理由很实在：

- **实时预览**，接近 Word 的所见即所得，不用在源文件和预览之间来回切；
- 支持 **LaTeX 公式**，`$...$` 和 `$$...$$` 都能直接写；
- 插件多，双链、标签、关系图这些整理笔记的功能都能加；
- 免费，下载完不用配置就能用。

<Figure src="/writing/obsidian.webp" alt="Obsidian 图标" caption="图 1　Obsidian 的图标" :width="88" />

下载地址是 [obsidian.md](https://obsidian.md/)，装完打开一个文件夹就能开始记。

### VSCode

写代码仓库里的 README、或者给博客写稿时，我用 VSCode：它原生支持 Markdown 预览，再装一个 **Markdown All in One** 插件就够用了。我常用的几项设置：

```json
{
  "markdown.preview.fontSize": 16,
  "markdown.preview.scrollPreviewWithEditor": true,
  "markdown.extension.toc.levels": "2..4",
  "markdown.updateLinksOnFileMove.enabled": "always"
}
```

真要说的话，两个编辑器没有高下之分：**记笔记用 Obsidian**（关系网、公式、插件），**写仓库文档和博客用 VSCode**（和代码放在一起，提交方便）。

## 二、最常用的几条语法

标题、表格、代码、图片、公式——这五样覆盖了我 90% 的写作场景。

### 标题

```md
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
```

注意**井号和标题内容之间要有一个空格**，`#标题` 是不生效的。一篇文章通常只用一个一级标题，下面用二级、三级分层，这样目录才清爽。

### 表格

用 `|` 分隔单元格，第二行用 `---` 分隔表头：

```md
| 名字 | 年龄 |
| --- | --- |
| 张三 | 13 |
```

### 代码

代码块用三个反引号包起来，开头写上语言名会有语法高亮：

````md
```python
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```
````

行内代码用一对反引号，比如 `Markdown`、`npm run docs:dev`。

### 图片

在 Obsidian 里直接把图片拖进编辑区，它会自动补全基础语法，后面还可以跟图片大小：

```md
![Alt text|300](图片链接 "optional title")
```

不过 `|300` 是 Obsidian 的扩展写法，标准 Markdown 和这个博客都不认。本站的图片统一放进 `docs/public/`，正文里用 `<Figure>` 组件引用，图注和图号也一起写在属性里——这算是本站自己的约定，和 Markdown 标准无关。

### 数学公式

行内公式用 `$` 包起来，独立公式用 `$$` 包起来，其它语法和 LaTeX 一样：

```md
质能方程 $E = mc^2$ 大家都见过。

$$
\int_a^b f(x)\,\mathrm{d}x = F(b) - F(a)
$$
```

::: warning 本站的一个小坑
在这个博客里，`$$` 必须**独占一行**（行首只能有缩进），否则公式会被当成普通文本；行内公式也不能跨行写。这是站点的渲染插件决定的，不是 Markdown 的问题。
:::

### 强调、链接、列表和引用

```md
**加粗**、*斜体*、`行内代码`
[链接文字](https://example.com)

- 无序列表
- 第二项

1. 有序列表
2. 第二项

> 引用：一句想突出的话
```

## 三、踩过的几个坑

- **井号后面忘记空格**：标题不生效，整行变成普通文字。这个错我犯过不止一次。
- **列表或表格前面没空行**：会被并进上一段，或者干脆被当成代码。写 Markdown 时「前后各空一行」是保命习惯。
- **图片路径写错**：Obsidian 的 `![[图片.png]]` 双链写法只在 Obsidian 里有效，换成博客或 GitHub 就失效。跨平台之前，最好把图片改成标准语法。
- **文件名随便起**：站点的文件我统一用英文小写加连字符（比如 `ch-01-latex.md`），中文文件名在链接和部署时容易出问题。

## 四、它和 LaTeX 怎么分工

用了这么久，我的结论是这两者不是替代关系：

| 对比 | Markdown | LaTeX |
| --- | --- | --- |
| 适合 | 快速记录、笔记、博客、文档说明 | 论文、报告、书籍等正式排版 |
| 书写 | 符号极少，几乎不打断思路 | 命令多，要适应 |
| 公式 | 够用，语法与 LaTeX 同源 | 出版级，环境完整 |
| 输出 | 交给编辑器或网站渲染 | 编译成 PDF |

我现在的习惯是：**课堂笔记和博客用 Markdown，课程报告和论文用 LaTeX**。两边都要写公式，但 Markdown 让我把注意力放在「记下来」，LaTeX 让我把注意力放在「排漂亮」。

## 五、最后一句

如果你刚开始用 Markdown，其实不用把上面这些背下来。**先写起来，遇到不会的再查**——被问的这位同学现在已经在用 Obsidian 记课堂笔记了，语法是写着写着就会的。

如果你用的正好是 Obsidian，那甚至连语法都可以少学一半：拖图片、点按钮、写公式，它都会帮你把 Markdown 补全。
