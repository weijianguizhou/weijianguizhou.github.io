# 第七章 · ROS 2 通信

## 7.1 Introduction

当涉及到底层通信时，通过在Linux命令行中执行一些相关操作可以更好地理解通信的工作方式。

通信，我们一直挂在嘴上。5G，6G这些我们经常会挂在嘴边。那通信的目的是什么？通信的原理是什么？通信的方式又是什么？

### 通信的目的

通信的目的是在计算机系统中实现不同组件、进程或设备之间的信息和数据传递。通过通信，各个实体可以共享信息、协调行动并实现协同工作。在计算机领域，通信是构建分布式系统、网络和协议的基础。

### 通信原理

通信的原理涉及两个主要方面：通信协议和通信方式。通信协议定义了数据的格式、传输方式、错误检测和纠正等规则，以确保可靠的数据传输。通信方式涉及了不同的通信介质和技术，包括网络通信和进程间通信（IPC）。

通信的原理确实是一个多层次、系统化的工程体系。无论是宏观的全球互联网，还是微观的操作系统内核，其核心都离不开**通信协议**（规范“怎么说”与“说什么”）和**通信方式**（解决“在哪说”与“怎么连”）的协同配合。

以下是对这两大核心论述的深度扩充。

### 通信协议的深度解析

通信协议是通信双方为了进行数据交换而共同达成的一套标准和规范。如果把通信比作人类对话，协议就相当于语言、语法、礼仪以及确认机制的综合体。为了保证复杂异构系统之间能够无缝交互，现代通信协议普遍采用**分层架构**（如 OSI 七层模型或 TCP/IP 四层模型）。

- **1. 数据格式与编码（Data Formatting & Framing）**

  - **报文结构**：规定数据包如何切分、如何组装。一个典型的数据包通常包含报头（Header，记录源地址、目的地址、协议版本、数据长度等控制信息）、有效载荷（Payload，实际传输的数据）和报尾（Trailer，用于校验）。

  - **序列化与编码**：将内存中的结构化数据转换为可在信道中传输的字节流。常见方式包括文本格式（JSON、XML）和高效的二进制序列化协议（Protocol Buffers、Thrift），以及物理/链路层的信道编码（如曼彻斯特编码、NRZ 编码）。

- **2. 传输规则与控制（Flow & Congestion Control）**

  - **流量控制（Flow Control）**：通过“滑动窗口”或“停止-等待”机制，确保发送方的发送速率不会压垮接收方的缓冲区，防止数据丢失。

  - **拥塞控制（Congestion Control）**：针对整个网络环境。当网络节点过多导致拥塞时，协议（如 TCP 的慢启动、拥塞避免、快重传与快恢复算法）会动态调整发送速率，防止网络发生瘫痪（拥塞崩溃）。

- **3. 差错检测与纠正（Error Detection & Correction）**

  - **错误检测**：由于物理信道存在噪声，数据在传输中可能发生比特翻转。协议采用循环冗余校验（CRC）、奇偶校验或哈希校验来识别数据是否损坏。

  - **错误纠正**：发现错误后，传统的“自动重传请求（ARQ）”机制会要求发送方重新发送；而某些对实时性要求极高的场景则采用“前向纠错（FEC）”，在数据中加入冗余纠错码，使接收方能直接修复错误而无需重传。

### 通信方式与技术架构

通信方式决定了数据在不同实体之间的流动路径和实现机制，按通信的物理范围和软件架构，主要分为**网络通信**和**进程间通信（IPC）**两大体系。

- **1. 网络通信（Network Communication）**

  - **底层介质与物理连接**：分为有线介质（如双绞线、同轴电缆、单模/多模光纤）和无线介质（如 Wi-Fi 射频、蜂窝移动网络 4G/5G、卫星通信），负责将比特流转换为电磁波或光脉冲进行物理传输。

  - **传输层与网络层（Socket 编程）**：基于套接字（Socket）抽象，通过网络层（IP 协议）实现跨网段的寻址与路由，通过传输层（面向连接且可靠的 TCP，或面向无连接且高效的 UDP）在主机间建立端到端的通信通道。

  - **应用层支撑**：在底层之上，衍生出丰富的应用层通信模式，如基于 HTTP/HTTPS 的请求-响应模式、基于 WebSocket 的全双工长连接、以及物联网中常用的 MQTT 协议。

- **2. 进程间通信（IPC, Inter-Process Communication）**

  - 用于单台计算机内部不同操作系统进程之间的数据交互。由于现代操作系统的**进程隔离机制**（每个进程拥有独立的虚拟地址空间），进程间不能直接访问对方的内存，必须依赖内核提供的专门机制。

  - 常见的 IPC 机制有：

    - **管道（Pipe）与命名管道（FIFO）**：基于文件抽象的半双工通信，适合具有亲缘关系的进程或简单的流式数据传输。

    - **消息队列（Message Queue）**：由内核管理的消息链表，进程可按类型读写消息，具备一定的异步解耦能力。

    - **共享内存（Shared Memory）**：效率最高的 IPC 方式。多个进程将同一块物理内存映射到各自的虚拟地址空间中，省去了数据在用户态和内核态之间的多次拷贝。

    - **信号量（Semaphore）与套接字（Local Socket）**：信号量用于多进程间的同步与互斥控制；而本地 Unix Domain Socket 则允许在单机内通过类似网络 Socket 的接口进行高效通信。

### 网络通信与进程间通信的维度对比

| **维度** | **网络通信（Network Communication）** | **进程间通信（IPC）** |
|:---|:---|:---|
| **应用场景** | 跨机器、分布式系统、微服务架构、互联网 | 单机多进程、操作系统内部服务协作 |
| **底层支撑** | 网卡、物理/无线介质、网络协议栈（TCP/IP） | 操作系统内核、虚拟内存管理、系统调用 |
| **性能开销** | 较高（受限于网络延迟、带宽、序列化与重传开销） | 较低（共享内存甚至可实现零拷贝） |
| **可靠性考量** | 需应对丢包、延迟、网络中断、恶意攻击 | 主要应对并发竞争、死锁、内存越界保护 |
